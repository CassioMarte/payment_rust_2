# Default 


- crio uma implementação para um model com valores default caso o front não envie nada 

- Primeiro eu altero o model

- #[serde(default)] -> deixa sua API tolerante a campos faltantes pois ela sabe que tem o default para completar os dados.

````
#[derive(Debug, Deserialize, Serialize)]
#[serde(default)]  //Novo para lhe dar melhor com defalt
pub struct NewPayment {
    pub amount: f64,
    pub currency: String,
    pub payment_method: PaymentMethod,
    pub payment_reason: String,
    pub status: PaymentStatus,
}
````

```
use crate::model::{NewPayment, PaymentStatus, PaymentMethod};


impl Default for NewPayment {
  fn default()-> Self {
    NewPayment{
      amount: 0.0,
      currency: String::from("BRL"),
      payment_method: PaymentMethod::Money,
      payment_reason: String::from(""),
      status: PaymentStatus::Pending,
    }
  }
}

let new_payment = NewPayment::default();
```

- Com o default ok eu posso usar ele aqui 
````
#[post("/payments")]
async fn create_payment(
    body: web::Json<NewPayment>, // recebe o JSON do cliente
    pool: web::Data<Pool<Postgres>>,
) -> impl Responder {

    // O cliente enviou só amount e payment_reason
    // Os outros campos assumem os defaults
    let mut new_payment = NewPayment {
        amount: body.amount,
        payment_reason: body.payment_reason.clone(),
        ..NewPayment::default() // currency=BRL, method=Pix, status=Pending
    };

    // Valida antes de salvar
    match new_payment.validate() {
        Ok(_) => { /* salva no banco */ }
        Err(e) => return HttpResponse::BadRequest().json(e)
    }
}
````


// Em testes por exemplo, é muito conveniente:
#[test]
fn test_amount_negativo() {
    let payment = NewPayment {
        amount: -50.0,          // só mudo o que importa pro teste
        ..NewPayment::default() // o resto não importa aqui
    };

    assert!(payment.validate().is_err()); // deve falhar
